(1) O QUE O ANDROID FAZ (referencia)
================================================================================
Arquitetura em 3 camadas:
  A. SmartJoinPlanner.kt (PURO, testado - 12 casos em SmartJoinPlannerTest.kt):
     - Entrada: por clipe -> {duracao, VideoProfile(codec,res,fps,rotacao,
       pix_fmt,sar,perfil), keyframes[]}
     - Escolhe o "target" (indice cujo perfil e compativel com mais duracao
       total) -> chooseTargetIndex.
     - Para cada clipe decide copyVideo (stream copy do CORPO entre keyframes)
       ou reencode (clipe incompativel ou keyframes esparsos).
     - Gera junctions (emendas) com bridgeStart/transitionStart/incomingEnd.
     - expectedDurationSeconds = soma - transicao * junctions (ou soma se fade).
     - Rejeita com motivo: codec/pix_fmt nao suportado, transicao cobre clipe,
       transicoes sobrepoem clipe intermediario.
  B. Execucao (FfmpegJoinVideosActivity.kt):
     - detectVideoKeyframes: MediaExtractor (ANDROID) -> no Windows usamos o
       showinfo do proprio ffmpeg (ja existe _extract_keyframes).
     - Para cada clipe com corpo > 0.020s:
       * copyVideo  -> ffmpeg -ss bodyStart -i clip -t bodyDur -c:v copy + audio
                      filtrado AAC -> MPEG-TS (h264/hevc_mp4toannexb,
                      -mpegts_flags +resend_headers+initial_discontinuity).
       * !copyVideo -> reencode do corpo com normalizacao de perfil -> MP4 ->
                      remux p/ TS (mesmos args de TS).
     - Para cada junction (emenda): gera BRIDGE recodificada:
       * fadeInOut: fim do clip A com fade out + inicio do B com fade in, concat.
       * xfade: prefixo de A + [xfade da cauda de A com cabeca de B] + sufixo de
         B (cada pedaco trim/split com setpts). Audio idem com acrossfade tri.
       * Resultado em MP4 -> remux TS.
     - Concat final: manifest concat demuxer de TODOS os TS -> -c copy ->
       MP4 com aac_adtstoasc, video_track_timescale 90000, faststart.
     - Validacao: duracao do container vs expected (tol = max(0.35, juncoes*0.12))
       e sincronia video/audio.
  C. Garantias: NUNCA reencoda tudo silenciosamente; se inviavel, interrompe
     com diagnostico. O audio de cada segmento e normalizado por janela.
